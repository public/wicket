- `wicket image --tag` keeps an explicit tag as given on an installed version; only the default
  becomes the build's own `wicket/claude-code:<build id>`. `wicket image --dir` passes that image as
  the Dockerfile's `BASE` build argument when it declares one, and `examples/self-hosting` builds
  on it, so a fresh node can build `wicket-self:dev`
  ([#277](https://github.com/public/wicket/issues/277)).
