- A node made with `wicket node create` no longer keeps billing after its lease ends. `create`
  records the node in the ledger with its lease end (minute 50 of the last paid hour of
  `--lifetime`), and the reconciler holds it to that lease. At the end, if no running run is placed
  on the node, the reconciler releases it through the placer, which checks the owner tag and
  `wicket-protected` first. It also revokes the node's enrolment and records a
  `reconcile.placed_released` audit record saying why. If a run is still on the node, the node is
  kept and a `reconcile.placed_held` record is written once each time the set of holding runs
  changes. `wicket node list` and the console's Nodes card then flag it as past its lease and
  still billing. A renewal decision for this case is part of
  [#56](https://github.com/public/wicket/issues/56); until then it is only a warning.
  `wicket node list` marks every node past its lease. With a Vultr `placement.yaml`, the capacity
  half of the reconciler no longer destroys recorded placed nodes as orphans
  ([#294](https://github.com/public/wicket/issues/294)).
