- Root runs only its own copies of wicket. `/usr/local/bin/wicket` (what `sudo wicket`, the root
  `wicket-follow` service and operators run) now links to `/usr/local/lib/wicket/<build id>/wicket`,
  root's, made by root from the artifact it names (`sudo wicket self update ARTIFACT`, the new
  `sudo wicket self admit ARTIFACT`, or `deploy/install.sh`), never from the `wicket` user's
  versions root, whose `current` wicket's services now run directly. A refused update's
  `apply-units` command names root's copy, and wicket refuses to run as root from a path the
  `wicket` user can write. A host installed before this needs `deploy/install.sh` from the new
  release's archive once, instead of `self update`
  ([#261](https://github.com/public/wicket/issues/261)).
