---
area: Nodes
type: Fixed
---
- Two runs on one node no longer get their freshness statements refused as replays. Each run sends
  its statements over its own connection, so the node can receive them out of order. A statement
  signed before the newest one the node holds is now checked as before, then dropped as superseded
  (the newer one already covers it), not refused. The statement the node holds, sent again, is
  still refused as a replay, and no older statement ever takes effect
  ([#300](https://github.com/public/wicket/issues/300)).
- A finished run whose files don't come back from its node now fails loudly instead of reporting
  them fetched. A node asked for a tree it doesn't hold refuses, where it used to send an empty
  archive. If the control host gets back an empty workspace (apart from `out/`) or other tree when
  the box started from a non-empty one, it replaces nothing here. The run is recorded as failed,
  with a `run.fetch_failed` audit record, and the node keeps the box's files, as it does for any
  failed fetch ([#300](https://github.com/public/wicket/issues/300)).
