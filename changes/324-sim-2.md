- Found by the deterministic simulation's new placement scenario
  ([#324](https://github.com/public/wicket/issues/324)), which runs `place create`, several runs on
  one placed node, the reconciler and the money envelope against a simulated provider, with
  partitions and crashes from a seed:
  - `wicket run --node` started boxes on a placed node past its lease, and each such run then held
    the node, so it went on billing for as long as new runs came. A placed node past its lease now
    takes no new run ([#294](https://github.com/public/wicket/issues/294)).
  - A run whose files its node kept because the fetch failed
    ([#300](https://github.com/public/wicket/issues/300)) didn't hold the node: at its lease end the
    reconciler released it, files and all. Such a run now holds its node, as a running run does,
    and `wicket node list` shows it holding; `wicket node release` still lets a human give the
    files up. The same holds a capacity lease whose run ended that way.
  - A reconciler pass that listed a node `wicket node create` had just made, before the create
    recorded it, destroyed it as having no lease. A node nothing records is now left alone for ten
    minutes after its creation; a crash's orphan still goes then.
  - With several runs on one node, a node refused another run's delta as a replay when an earlier
    catch-up had already carried it (the #300 refusals, for deltas). A delta the node already holds
    is now taken as superseded, as an older statement is.
- The simulation also gains a messages scenario (principals, held messages, a hibernated agent's
  wake and receipts, across restarts and cut-offs). It finds that a message can be lost when the
  answer to a box's relayed `await_message` is cut off after the control host recorded it read; the
  fix (acknowledged delivery) is left for later, and the loss is reported meanwhile.
